# OPC Skills

OPC Skills 是一个面向一人公司、独立开发者和小团队的开源 Agent Skills 集合。它包含产品机会研究、SEO 专项研究，以及有来源依据的 AI/科技选题和 X 文案制作。热度不等于商业机会，吸睛的标题也不等于事实已经得到证实。

## 八个平级 Skill

| Skill | 职责 |
| --- | --- |
| `product-opportunity-finder` | 通用产品机会入口：从当前社交、开发者、社区、发布和产品信号中找用户能理解的差异化产品，再检查现有替代品、成功路径、执行条件与分发方式。 |
| `seo-idea-finder` | 自包含总入口：从真实站点、页面、查询、客户任务或变化记录中持续挖掘，直到用户要求数量的机会通过基础准入门槛。 |
| `site-opportunity-scout` | 研究小站和增长站点，区分已验证事实、第三方估算、站长自述与推断。 |
| `keyword-demand-validator` | 验证关键词需求、趋势、意图与点击潜力，严格区分不同指标。 |
| `serp-competition-auditor` | 从页面、运营者、搜索意图和 SERP 功能层面检查真实竞争。 |
| `solo-business-evaluator` | 判断机会是否适合独立开发者实施、维护、防守和变现。 |
| `ai-tech-topic-scout` | 找 AI/科技最新消息、演示和有讨论价值的选题，核验来源、日期与值得写的角度。 |
| `x-post-writer` | 根据有来源的素材和传入的账号背景，写 X 主帖、回复或系列续篇；缺少当前资料时使用选题 Skill。 |

每个 `skills/<name>/` 都能分别安装。Skill 内的 `references/` 只是按需读取的参考材料，不是新的 Skill。X 写作依赖已核验的信息：给定资料时可单独编辑；从找消息到出稿则由两个编辑类 Skill 串联完成。

这套 Skill 不依赖 Marketing Skills 或其他 Skill 仓库才能运行。我们可以吸收公开项目中有价值的方法，但每个已安装 Skill 都必须自带完成自身任务所需的指令。

## 安装

这个仓库不需要 `package.json`；`npx` 运行的是外部 [`skills`](https://github.com/vercel-labs/skills) CLI。

在本地克隆目录中查看可安装项：

```bash
npx skills add . --list
```

安装通用产品机会 Skill：

```bash
npx skills add . --skill product-opportunity-finder --agent codex --global --yes
```

只安装 SEO 自包含主 Skill：

```bash
npx skills add . --skill seo-idea-finder --agent codex --global --yes
```

安装 AI/科技选题与 X 写作这两个 Skill：

```bash
npx skills add . --skill ai-tech-topic-scout x-post-writer --agent codex --global --yes
```

安装全部八个 Skill：

```bash
npx skills add . --skill '*' --agent codex --global --yes
```

从公开 GitHub 仓库直接安装：

```bash
npx skills add boh5/opc-skills --skill product-opportunity-finder --agent codex --global --yes
npx skills add boh5/opc-skills --skill seo-idea-finder --agent codex --global --yes
npx skills add boh5/opc-skills --skill '*' --agent codex --global --yes
```

仓库同时包含 `.codex-plugin/plugin.json`，因此也可以把整套内容作为一个仅包含 Skills 的 Codex Plugin 分发。`product-opportunity-finder` 可以独立完成非 SEO 产品机会研究。只安装 `seo-idea-finder` 不会安装或自动调用另外四个 SEO 专项 Skill；SEO 主 Skill 会完成基础检查，完整安装后才能显式调用专家 Skill 做深度复核。

只安装 `x-post-writer` 也不会自动安装选题 Skill。需要从最新消息开始时，使用上面的成对安装命令，并让运行环境同时提供这两个 Skill。它们不会自行安装、建立定时任务或发帖。公开仓库安装命令只有在这些新增改动推送后才会包含新 Skill。

公开提交到 Plugins Directory 还需要经过验证的开发者或企业身份、政策声明、评审用例和通过 Skill 扫描。对于当前这个纯 Skills Plugin，网站、支持、隐私和条款 URL 是可选项；如填写，必须是与发布者匹配的真实公开 HTTPS 地址。详见 [发布检查清单](docs/release-checklist.md)。

## AI/科技选题 → X 草稿

写作 Skill 已内置 Humanizer 3.0.0 原版引用。每次初稿完成后执行去 AI 味编辑，再复核事实和最终长度，无需另装 Humanizer。

自动选题优先“暴论、事实、发现”：有理由的鲜明判断、有信息量的事实，或值得分享的观察与新用法，至少有一样能撑起这条内容。新帖、回复和引用都适用，不要求每条三样全占。Humanizer 和后续口语编辑要保住核心主张与细节，同时保留事实边界。

个人帖先确定自己想说什么：观点、可公开的经历、围绕热点的想法或真想讨论的问题，都能独立成帖，不必先找一条新闻。涉及外部事实再核验，正文不强塞发布日期、资料摘要或文章链接；借用别人的具体结果和论点仍须明确署名。没有外部链接的原创观点可以用空的来源数组交付。不能虚构亲测或经历，明确要求新闻摘要或教程时仍按要求写。Skill 内附[实际查看过的中文 X 文案样本](skills/x-post-writer/references/chinese-x-patterns.md)。

用户没有指定形式时，按内容和现有讨论选择新发、回复或引用，没有默认优先项或固定比例。选择回复／引用时，交付目标原帖、简短上下文和可用文案，目标链接放在正文外。个人观点正文默认不带资料链接；核验资料留在复核信息里。先检查读者脱离提示词和资料页能否读懂，再检查字数。

配图按需：能增加信息、感受或笑点就配，单纯重复正文就不配，纯文字也可以是完整成品。需要配图时使用合适素材，或由运行 Skill 的 Agent 明确画面意图、构图和图中文字后生成并检查；“交接示意”等制作说明留在图外。用户明确要图时，交付实际图片或如实说明阻碍。详见 [配图交付说明](skills/x-post-writer/references/images.md)。

原创插画默认用正常彩色的抽象简笔画，通过夸张表情、动作和比例制造戏剧感与荒诞幽默。Skill 附带可安装的风格参考图和生图用的具体要求；每次按帖子内容重新构思场景，不固定复用参考图的道具和构图。明确指定的其他画风、真实截图和数据图仍按各自需要处理。

持续写作时，可以传入账号定位、认可的文风样本、可公开素材、已写／待发／已发内容和读者反馈。Skill 据此选择新帖、续篇或回复，也可以返回“本轮不出稿”。支持有依据的反共识观点，直接挑战具体论点或常见做法，不虚构争议或个人信念。案例和解释类内容不必都是最近新闻，但仍须保留日期、来源和限制。历史记录由调用方保存；Skill 不负责调度、自动记忆或发布。可选的结构化交接见 [账号上下文说明](skills/x-post-writer/references/account-context.md)。

直接调用写作入口，需要时再补资料：

```text
使用 $x-post-writer，围绕我给的话题，结合我的关注点和立场，选择值得表达的内容。由你判断适合新发还是加入已有讨论，再给中文文案，按内容需要决定是否配图。需要了解当前讨论或核验事实时，用 $ai-tech-topic-scout。只出草稿，不发布。
```

只想看选题时：

```text
使用 $ai-tech-topic-scout，找最近 48 小时最多 5 个 AI/科技选题，说明发生了什么、为什么值得写、建议角度、来源日期和关键限制。区分真实观察到的讨论与可能引发讨论的判断。
```

前一步交付 `opc-topic-pack/v1` 信息包，保留事件标识、来源、事实、限制和时效。后一步复用当前信息包，不重做整轮搜索；缺证据或关键消息过期时只补查相关部分。无法访问的数据保持未知，不编造新闻、热度、测试体验或爆款概率。公开网页研究不要求 X 登录、额外模型 API 或你的私有项目；无法查看 X 时也不会声称已经核验 X 热议。

需要新闻发现时默认扫描最近 48 小时，最多推荐 5 个选题。写作默认交付一个最值得采用的动作，按内容选择新发、回复或引用；用户指定形式或要求多条时照做。直接观点写作不必扫描新闻。数量是上限，宁缺毋滥；正常无新消息与访问失败分别报告。草稿保留实际使用的来源、必要署名、合适格式和长度检查结果。可选校验脚本使用 `twitter-text` 处理中文、Emoji、链接和线程编号，不把普通字数当作 X 长度。

这两个编辑类 Skill 的 0.2 版增加独立的受众筛选：官方、真实、近期，不等于普通读者值得看，必须有来源支持的具体看点。活动日期不能当成所有功能的发布日期；是否完成看约定范围，而不是搜索次数，未完成的必需检查不能推进成功扫描记录。可选长度脚本增加 JSON 标准输入，无需临时草稿文件，但仍须遵守运行环境权限；校验结果必须对应最终交付的原文。

后续配置周期任务时，传入账号上下文，让 Skill 先选要表达的内容，再按需补查、写作。新闻发现另传时区、窗口和预算；有保存需求时传明确目录。信息包可在对话中交接，不必落盘；保存时使用准确的运行 ID，并区分“看过、写过、实际发布过”。Skill 本身不是调度器，也不会因为被定时调用就获得发帖权限。

## 验证与辅助脚本

`evals/` 里有真实提示词、失败条件和评分标准，用来验证 Skill 是否会编造数据、混淆指标、过度外推或给出含糊结论。它不是空目录。

编辑类 Skill 自带局部 `scripts/`，分别检查信息包交接和 X 加权长度。X 校验器使用局部锁定的 npm 依赖；仓库根目录仍然不需要 npm 应用，也没有绑定某个抓取器。安装与测试命令见 [evals/README.md](evals/README.md)。结构检查和样例测试不等于涨粉效果验证。

## 产品与 SEO 研究模式和项目上下文

- `product-opportunity-finder` 从当前痛点、变通做法、请求、变化、发布、Issue 或采用记录开始。X、Hacker News、GitHub、Reddit、Product Hunt、Indie Hackers、V2EX、Linux.do 和目标用户社区是发现渠道，不是市场成立的证明。
- 通用产品候选必须让目标用户听得懂、完成真实工作流、通过功能等价竞品检查、说清第一批用户从哪里来，并且符合开发者约束。冷门不等于机会。
- 现有竞品不是自动否决。有产品已经做了某项功能时，只能否定这个功能差异点；细分人群、工作流、分发、信任、数据、服务、速度或经济模型仍可能形成真实切口。
- 研究成功项目时，要把产品本身的价值与社交或平台放大分开，把可复用方法与时机、既有受众、资本、专有资源和运气分开。最终产生的新机会还要重新查当前替代品，不能复制原产品。
- 两个入口 Skill 都把用户要求的数量当成交付目标。被淘汰、重复、含糊或只剩“继续研究”的项目不能占位；不够就继续挖，除非出现真实阻塞。

- 先根据已有条件选择一个主发现模式：现有网站扩张、已知人群/市场、开放式跨市场挖掘，或新词快攻。
- 每个候选都必须追溯到真实的第一方、站点、页面、查询、客户任务、SERP 或变化记录。X、社区、评论和站长故事只能提供线索，不能证明搜索需求或低竞争。
- 开放式挖掘优先使用已授权的站点、页面或查询数据源。没有平台数据时仍可使用公开网页证据，但必须明确来源，缺失指标保持未知，不能冒充完整的平台关键词研究。
- 先用便宜的准入门槛淘汰弱候选，再做深入检查。进入昂贵验证前，要按用户、输入、处理过程、输出、工作流限制、所属生态和购买方式建立“产品功能指纹”，再去官方产品页面反查名字不同但实质相同的现有产品。
- 用户要求的 `N` 是完成目标。被淘汰、重复、需求与 SERP 都未知、只有“值得研究”的候选不能占位；不够就继续从真实数据里挖下一批。
- 只有用户硬性预算、数据源耗尽、缺少授权或必要数据确实无法访问时，才能以不足 `N` 结束，并且必须明确说明任务未完成，不能用弱候选补满。
- `quick`、`standard`、`deep` 只表示证据深度，不再强制 `4N` 候选池或任意的外部观察次数公式。公开网页模式会把决定性的竞品撞车检查提前；一个切入点已经失效就立即换下一个，不再为它写完整长报告，达到 `N` 个通过项后即停止常规挖掘。
- 默认汇报先讲具体产品和首选，不展示内部候选账本、查询计数或工具轨迹；只有用户要求尽调或可复核记录时才附加。
- 有竞品不是自动否决。如果竞品已经具备我们声称的功能，只否定这个差异点，再检查产品、细分人群、数据、工作流、分发、信任、服务、速度或经济模型是否仍有真实优势。只要对产品做了实质性改题，就必须重建功能指纹并重新反查竞品，不能沿用原题的结论。
- 一个实时链接不等于保存了当时的观察。关键证据需要记录观察时间、数据周期、市场/设备、提取方式、支持的结论与限制。
- 数字止损线必须说明依据：历史基线、样本/统计目标、实验成本与最低回报，或用户设定的目标；没有依据时先给校准周期或公式。

项目可以选择提供 `.agents/opportunity-research.md`，保存市场、语言、开发者能力、排除项和已批准数据源等稳定事实。它不是必需文件，也不会授予写文件、登录、购买、发消息或扩大研究范围的权限；除非用户明确要求，否则 Skill 不会创建或修改它。

## 核心原则

- 事实、第一方测量、第三方估算、站长自述和推断必须分开。
- 搜索量、趋势指数、SEO 难度、广告竞争、排名、站点流量和收入不是同一个指标。
- 同义词搜索量不能直接相加；同一运营者的多个域名要合并判断。
- 单次本地化 SERP 只能算带日期的样本，不能说成稳定的全国排名。
- 必须按功能指纹反查当前产品，不能把“搜不到自创名称”当成“没有同类产品”；功能撞车只否定这个切入点，不等于整个市场自动无效。
- 产品/SEO 研究中，只有用户要求数量的来源可追溯候选都通过准入门槛才算正常完成；如果遇到真实阻塞，必须把不足数量明确标为未完成，不能拿未知或淘汰项补位。
- 完整产品/SEO 研究要给出排序产品、第一选择、切入优势、投入和持续工作、风险与有依据的止损线。编辑选题则按数量上限精选，不凑数，也不强加产品商业论证或 SEO 检查。
