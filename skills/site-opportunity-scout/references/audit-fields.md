# Site audit fields

Use the smallest subset that answers the question. For a batch, keep one row per operator and link related domains in `related_properties`.

| Field | What to record | Common mistake |
| --- | --- | --- |
| `research_mode` | Quick, standard, or deep plus planned/used workload | Treating a workload budget as proof quality |
| `canonical_url` | Live canonical product or domain | Mixing a product with its parent company's portfolio |
| `operator` | Person/company plus evidence | Treating privacy-protected WHOIS as proof of independence |
| `related_properties` | Domains, apps, acquisitions, redirects | Counting one network as many competitors |
| `product_launch` | Best-supported window and source | Using domain registration as launch date |
| `product_job` | Actual task the product completes | Repeating the marketing category |
| `working_functionality` | Tested, partial, gated, broken, or unknown | Assuming a landing page proves the tool works |
| `claimed_entry_edge` | Feature, segment, data, workflow, distribution, trust, support, speed, or economics claim | Calling marketing wording a differentiated product |
| `closest_alternative` | Current product or workflow used for parity comparison | Comparing only category labels or old competitors |
| `parity_or_gap` | Observed capability match, partial gap, material gap, or unknown | Rejecting the entire opportunity when one feature is already present |
| `surviving_entry_thesis` | Material advantage still available after parity check | Treating competitor existence or traffic as a veto or proof of access |
| `indexable_system` | Page types with independent user value | Counting parameter or synonym pages as products |
| `traffic_metric` | Metric name and value | Calling total visits “organic traffic” |
| `provider_scope` | Provider, month, country, device | Presenting a model without its boundaries |
| `evidence_record` | Source URL/ID, class, observed time, data period, extraction method, claim, limitation | Assuming a live URL preserves the prior observation |
| `trend` | Several comparable periods | Calling one snapshot growth |
| `top_pages_queries` | Page/query families and source | Inferring sitewide demand from the homepage |
| `acquisition_mix` | Search, direct, referral, paid, social, email | Assigning all growth to SEO |
| `monetization` | Observed mechanism versus claimed result | Converting estimated visits into revenue |
| `moat` | Data, links, brand, community, distribution, workflow | Treating domain authority as the only barrier |
| `ongoing_operations` | APIs, curation, moderation, support, sales | Estimating only initial build time |
| `reproducibility` | Strong, mixed, weak, or unknown with reason | Treating correlation as a replicable playbook |

For acquisition diligence, add direct analytics, cohort or retention evidence, concentration, costs, liabilities, financial definitions, and seller identity. A public SEO audit is not financial due diligence.
