# 替本人说话

## 中文口语

这是一条个人 X。想象有个熟人问你“你对这事怎么看”，把回答直接写下来。用日常会连着说的句子，不要先写一段分析，再把它压缩成帖子。

一条帖有一个值得说的意思就够了。可以从眼前的小事、选择或具体问题开口，顺着说下去；没必要先宣布“作为开发者，我认为”。例子已经把想法说明白时就停，不用另提炼一条原则。长短、分段、问句由这次内容决定。

**完整自然的句子优先于短。** 日常话里的“把……做完”“点这个按钮就能……”不是赘词。压缩后若变成一个概括名词接半句话，恢复原本的动作和关系。别让读者替你补主语或猜动词的对象。整帖太长就少讲一点，不要把每句都剪得更短。

口语不是一种固定口癖。技术名词在读者需要时照用，周围的话正常说；不靠俚语、脏话、语气词或不断反问来装熟。用户的提纲可以很正式，保留意思即可，不必把提纲的第一句当成正文开头。

下面是虚构练习，只展示怎么把意思讲成日常话，不是可复制的帖子、真人经历或固定句式：

| 想表达的意思 | 一种日常说法 |
| --- | --- |
| 不愿被产品捆住，担心搬走资料很麻烦 | 东西能随时搬走，我才敢一直用。要是换个软件就得从头整理，我连现在这份资料都不想继续往里放。 |
| 虚构练习给定的经历：录了十分钟，保存失败，录音没有留下 | 录了十分钟，点保存才告诉我失败了，刚才那段也没留下。就不能先把录音留在我电脑上吗？ |

第一种是偏好，第二种要有给定的真实经历才能用于本人账号。不要把参考例子、别人的故事或写作 Agent 的操作算成本人经历。

## 内容从哪里来

用用户给的观点、经历或问题确定这次要说什么。事实材料可以支持它，不必决定全文结构。没有个人经历，可以提出有理由的当下判断或清楚标明的设想；没有事实来源，不能增加外部能力、数据、测试结果或“大家都”的断言。

自动选题时，关心内容给读者留下了什么：一个可用的答案、影响选择的细节、值得比较的取舍、真实的经历或有内容的疑问。只把产品名换掉仍成立的“我会先试试，再看准不准”，通常没提供多少东西。明确的常青观点不要求借热点；用户要求新闻摘要、教程或材料改写时，按那个目的写。

让相关读者愿意接话，可以来自他们经历过同样的问题，也可以来自他们不同意某个具体判断。不是每帖都要问“你怎么看”，有用到值得保存的内容也成立。不许编“业内都这么想”来制造冲突，也不靠辱骂、骗互动或夸大承诺填补内容。

## Contrarian angles

敢讲有理由的不同意见：针对一个具体说法、惯常做法或真实讨论，指出反例、漏掉的条件或不同取舍。用户给了信念就保留它的力度；没有给时可以提出可辩护的判断，别编“我一直坚信”。

反共识要有实际对照。没有证据说明别人持相反观点，就直接说自己的主张。影响判断的反例和适用条件放进同一条表达，不留到被质疑时才补。观点可以尖锐，事实不能跟着加码；“我认为所有人都已经……”仍是在断言外部事实。

争议只是可选切口。自动选题时，有用的回答也可能比反驳更适合。点赞、争吵或大号转发不能单独证明内容好或能涨粉。

## Attribution and added value

分清三件事：

- 核验：事实依据和 URL 留在正文外的复核信息。原创偏好或用户提供的经历可以没有公开来源。
- 署名：借用特定作者的成果、数字、引语、论点或演示，用自然的话说明是谁的。原生引用有时已经提供这一上下文。不要把借来的东西写成自己的发现。
- 给读者入口：默认不往评论正文塞研究链接。用户明确要分享资源，或查看特定原文就是这条帖的目的时，再放正文链接。署名不等于必须附一个 URL，链接也不能代替解释。

厂商展示、作者自述、自己的判断分清楚。保留影响含义的版本、条件、日期和限制；无关审计信息留在复核中。视频没看过就不写“视频展示了”；设想的失败不写成已知产品缺陷。转述要简洁，保留许可要求，不做整篇翻译或逐句换皮。

## 语言编辑

完成 Humanizer 处理后，做一轮语言编辑。使用宿主已有且获准的子代理能力时，编辑从干净上下文开始（支持时设置 `fork_context: false`），只接收候选正文、受众、表达意图和必须保留的事实／署名。回复／引用另给可见原帖。不要传入写作者的推理、自评分、历史稿或过去的测试批评；不为这一步安装服务或创建用户侧任务。

给编辑的是下面这种明确的文字工作，不是“打分看看好不好”：

> 这是个人 X 的纯文字编辑任务。把候选正文想说的意思，重新讲成一段跟熟人聊天时会说的话。保留立场和必要信息，不必保留原来的句式和段落。如果一句例子已经说清了意思，可以删掉重复的概括；不要把短帖扩成一份实施方案。让句子完整、语序自然，不靠俚语、脏话或语气词造口气。保留给定事实、限制和署名，不增加经历、情绪、承诺或外部事实。回复要接得上给定原帖。只返回编辑后的正文，不打分、不评可发性、不出多个版本。不用工具、文件、联网、图片或进一步委派。

一次写作只做这一轮委派，不把编辑结果再交给一串评委反复修。没有可用委派时，由当前 Agent 执行同一编辑任务。日常交付无需叙述内部人员分工，不能把独立编辑说成独立事实核验。

写作者拿到编辑稿后核对：意思、事实范围和必要署名是否保留，是否凭空增加了经历或能力，以及只看正文能否跟上意思。语言变动不能越过这些边界；对不忠实的地方做必要修正，不把自然的话又扩写成分析。之后才做最终长度和图片工作。

这一轮编辑是 Skill 本身的写作流程，发生在首次成品交付之前。外层维护测试仍要保留首次成品，不能把测试反馈发回作者或编辑修稿。自评、模型好评和长度通过都不等于用户接受；用户指出的具体问题保留为失败证据。
